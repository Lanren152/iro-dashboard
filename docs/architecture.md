# 架构说明

系统以 PostgreSQL 为持久核心，任何模型都只是可替换的推理组件。研究流程分成五个确定性层级：采集与校验、事实存储、异常检测、研究状态机、审计与评估；大模型只负责资料理解、跨文档推理、产业假设、公司映射和反方审查。

## 全市场扩展方式

行业覆盖由 `data/sectors.json` 和 `data/metric_templates.json` 驱动。新增或细化行业时，不修改研究引擎，只增加行业目录、指标定义和数据连接器。通用指标模板提供初始扫描能力，正式生产时再为每个行业配置特有指标、领先关系、季节性和来源授权。

## 主流程

```text
数据连接器 → 原始资料/时间序列 → 数据校验与去重 → 指标异常扫描
→ 产业验证 Agent → 公司映射 Agent → 反方 Agent → 机会状态机
→ 前端/MCP → Codex 或 Claude Code
```

## 可靠性边界

- 时间序列的异常检测和所有财务运算由 Python 完成。
- LLM 输出必须是结构化对象，并保存输入摘要、模型、耗时和输出。
- 状态迁移写入 `StateTransition`，不能覆盖历史。
- 原始文档以内容哈希去重，发布时间和数据所属期间分开保存。
- MCP 工具只操作研究系统，不暴露交易下单能力。
